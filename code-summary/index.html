แผนที่โค้ด LUMA

สรุปว่าแต่ละไฟล์ทำอะไร ส่งข้อมูลต่อให้ใคร และคำขอหนึ่งครั้งเดินทางผ่านโค้ดส่วนไหนบ้าง ตั้งแต่กดปุ่มบนหน้าเว็บจนได้รูปกลับมา ชื่อไฟล์ทุกอันในหน้านี้กดเพื่อไปดูรายละเอียดไฟล์นั้นได้

หน้าเว็บ (React) nginx Backend (Flask) AI Server (Stable Diffusion) Database (SQLite)
ถ้าต้องอธิบายใน 1 นาที
  1. LUMA เป็นเว็บที่ทำได้ 2 อย่าง: สร้างรูปจากข้อความด้วย AI (Stable Diffusion) และ แต่งรูปที่อัปโหลด (เบลอเฉพาะจุด, การ์ตูน, ลบพื้นหลัง, จับท่ามือ ฯลฯ)
  2. ระบบแยก 3 เครื่องในวง LAN: nginx (172.20.57.12) เป็นประตูเดียวที่ผู้ใช้เข้า, Backend (172.20.57.16) คิดงานและเก็บข้อมูล, AI Server (172.20.57.10) มีการ์ดจอไว้สร้างรูป
  3. nginx ส่งไฟล์หน้าเว็บ (React ที่ build แล้ว) ให้ browser และส่งต่อทุกคำขอที่ขึ้นต้นด้วย /api/v1/ ไปที่ Flask
  4. Flask ตรวจ token (JWT) ว่าเป็นใคร, ตรวจค่าที่ส่งมา, ถ้าสร้างรูปก็ส่งต่อให้ AI Server แล้วเก็บรูปลง SQLite + โฟลเดอร์ uploads, ถ้าแต่งรูปก็คิดเองด้วย OpenCV/MediaPipe แล้วส่งรูปกลับเลย
  5. ทุกคำตอบของ API อยู่ในรูปแบบเดียวกัน {"success": true, "data": …} หรือ {"success": false, "error": {code, message}} หน้าเว็บมีไฟล์เดียว (client.js) ที่แกะรูปแบบนี้ให้ทุกหน้า

07 · Image Processing

อัลกอริทึมแต่งรูป

ทั้ง 6 เครื่องมือรันบน CPU ของเครื่อง Backend ไม่ใช้ AI Server และไม่บันทึกลงประวัติ ทุกตัวใช้ขั้นตอนเหมือนกันใน : เช็คไฟล์ (.jpg .jpeg .png .webp) → ตรวจค่าพารามิเตอร์ → _decode_image() (ไม่เกิน 20 ล้านพิกเซล) → เรียกอัลกอริทึม → แปลงเป็น PNG ส่งกลับ

Spot Blur

  1. เบลอทั้งรูปเตรียมไว้ (Gaussian, kernel = strength×2+1)
  2. วาดวงกลมสีขาวลง mask ตามจุดที่ผู้ใช้ระบาย
  3. เบลอขอบ mask ให้นุ่ม (จำกัดไม่เกิน 151 px)
  4. ผสม: ตรง mask ใช้รูปเบลอ ที่อื่นใช้รูปเดิม

Cartoonize

  1. Bilateral filter หลายรอบ: ผิวเนียนแต่ขอบยังคม
  2. K-Means ลดสีเหลือ k สี (num_colors) ให้สีเป็นก้อนแบบการ์ตูน
  3. หาเส้นขอบ: median blur + adaptive threshold แล้ว erode ให้เส้นหนาขึ้น
  4. เอาเส้นดำทับภาพสี

Tilt-Shift

  1. เพิ่มความสดสีในระบบ HSV และเพิ่ม contrast ให้ดูเหมือนของเล่น
  2. ทำรูปเบลอเตรียมไว้
  3. สร้าง mask แนวตั้ง: ใกล้เส้นโฟกัส = ชัด ไกลออกไป = เบลอ (ไล่แบบ cosine)
  4. ผสมรูปชัดกับรูปเบลอตาม mask

HDR Enhancer

  1. Gray World: ปรับให้ค่าเฉลี่ย R G B เท่ากัน (แก้สีเพี้ยน)
  2. แปลงเป็น LAB แล้วใช้ CLAHE กับช่องความสว่าง L เท่านั้น
  3. Unsharp mask: ดึงรายละเอียดความถี่สูงมาเพิ่ม

Remove Background

  1. ย่อรูปให้ด้านยาวไม่เกิน 900 px (GrabCut ช้าตามขนาดรูป)
  2. MediaPipe Selfie Segmentation ให้ค่าความน่าจะเป็นว่าแต่ละจุดเป็น "คน"
  3. ไม่ได้ลากกรอบ/ระบาย: ใช้ผล AI ตรงๆ เก็บก้อนใหญ่สุด
  4. มีกรอบ/แปรง: สร้าง mask เริ่มต้นจากกรอบ + AI + เส้นแปรง (เก็บ/ลบ = คำตอบแน่นอน) แล้วรัน GrabCut 4 รอบ
  5. ขยาย mask กลับขนาดจริง ทำขอบนุ่ม ลบสีพื้นเดิมที่ติดขอบด้วยสมการ F = (I − (1−a)·B) / a
  6. ส่งกลับเป็น PNG โปร่งใส หรือเติมสีพื้นที่เลือก

Hand Gesture

  1. MediaPipe Gesture Recognizer โหมดรูปนิ่ง (โหลดโมเดลครั้งแรกแล้วเก็บไว้ใช้ซ้ำ)
  2. ได้ชื่อท่า 7 แบบ (กำมือ, แบมือ, ชูนิ้วโป้ง ฯลฯ) + ความมั่นใจ + มือซ้าย/ขวา + จุด 21 จุดของแต่ละมือ
  3. ตอบเป็น JSON (ไม่ใช่รูป) เลือกมือที่มั่นใจที่สุดเป็นผลหลัก

MediaPipe ใช้พร้อมกันหลาย thread ไม่ได้ ทั้ง remove_bg.py และ gesture.py จึงมี threading.Lock() ของตัวเอง ไฟล์โมเดลอยู่ใน backend/models/ (ถ้าไม่มี จะดาวน์โหลดตอนใช้ครั้งแรก หรือรัน ไว้ก่อน)

09 · ข้อสังเกต

สิ่งที่ควรรู้ก่อนอธิบายโค้ด

ผลแต่งรูปไม่เข้าประวัติ

มีแต่ /generate ที่บันทึกลงตาราง generations เครื่องมือ /process/* ส่ง PNG กลับให้ดาวน์โหลดอย่างเดียว ค่า category = 'image_filter' ในโมเดลเตรียมไว้รองรับในอนาคต

มี 6 เครื่องมือ แต่โชว์ 4

Tilt-Shift กับ HDR Enhancer ทำเสร็จทั้งฝั่ง backend และหน้าเว็บ แต่ ACTIVE_FEATURE_IDS ใน ใส่ไว้ 4 ตัว (animation ของหน้า Features ตั้งไว้สำหรับ 4 ช่อง)

ค่าเริ่มต้นในหน้า Settings ยังไม่ถูกใช้

หน้า Settings บันทึกโมเดล/ขนาด/steps เริ่มต้นลง localStorage ผ่าน แต่ ใช้ค่า DEFAULTS ของตัวเอง ไม่ได้อ่านค่าที่บันทึกไว้ ส่วนธีมสีและเลย์เอาต์ใช้งานได้จริง

เมนู Admin ซ่อนเพื่อความสวยงามเท่านั้น

หน้าเว็บซ่อนเมนูจาก role ใน localStorage ซึ่งผู้ใช้แก้เองได้ ด่านจริงคือ @admin_required ที่อ่าน role จากฐานข้อมูลทุกครั้ง ไม่ได้เชื่อค่าใน token

ตรวจค่าซ้ำ 2 ฝั่ง

หน้า Generate ตรวจ prompt/ขนาด/steps ก่อนส่งเพื่อให้ผู้ใช้เห็น error เร็ว แต่ sd.py ตรวจซ้ำทุกครั้ง เพราะใครก็ยิง API ตรงได้โดยไม่ผ่านหน้าเว็บ

คิว GPU อยู่ในหน่วยความจำ

_gpu_lock เป็นตัวแปรใน process เดียว ถ้ารัน Flask หลาย process คิวจะแยกกันแล้วยิงชน GPU จึงตั้ง workers = 1 แล้วใช้ thread แทน

ID ถูกใช้ซ้ำได้

ตารางที่ Flask สร้างไม่มี AUTOINCREMENT ลบคนล่าสุดแล้วคนใหม่อาจได้ id เดิม jwt_auth.py จึงเช็คว่า email ใน token ตรงกับเจ้าของ id ปัจจุบันด้วย

ไฟล์เก่าที่ไม่ได้ใช้

frontend/index.html (หน้าเว็บต้นแบบไฟล์เดียว), frontend/luma-frontend.zip (สำเนาเก่า 19 MB), backend/.env.mine (ว่าง) และโค้ดที่ปิดด้วย # ท้ายไฟล์ sd.py, history.py, profile.py, routes.py, gesture.py ระบบไม่ได้เรียกใช้
